# Questionnaire configuration notes

`questionnaire.json` is developer configuration for original proposed wording. It contains no career weights and is not a validated psychological assessment. Content still needs SLC review and learner testing.

- Career: C1–C6, plus optional C7 only for a material unresolved comparison with a reviewed scenario pair. Personal interest is a goal in C1; C3 and C4 switch to activity wording for that goal.
- Courses: F1–F5, plus at most one optional F6 from a reviewed course requirement rule. F4 time and F5 price are optional and skippable. C7 and F6 are also skippable. Other questions include an uncertainty/exploration answer where applicable.
- F2 includes all 16 exact source category names from `catalog_audit.json`, readable learner labels and stable snake-case identifiers. The SLC catalogue does not define the limits of career exploration. Exact-course search can bypass the questionnaire.
- F1 can show a separate optional exact requirement/qualification-name field only for `specific_requirement`. F3 can show an optional previous-qualification field. These have different meanings and IDs; never merge them. F5 shows the optional amount field only for `enter_maximum`; a missing amount applies no cap. Inline fields are explicitly disclosed. If a developer puts an optional field on another screen, the visible screen count must increase.
- Reuse is deliberately conservative. C1 first-work/career-change/personal-interest goals map to F1. Progression, return-to-work and career exploration ask F1. C5 can map only with a recorded, specific, unchanged subject context. Studied is not completed, previous work is not current work, and study plus work is not proof of a qualification. Non-equivalent or missing values ask F3.
- All unknown options are marked `isUnknown` and `exclusive`. In multi-select C4, “a mix” is also exclusive but is not unknown. Enforce mutual exclusivity in both client and server validation.
- Dynamic C7/F6 labels are bindings, not permission for an AI to write scored questions. A reviewed scenario/rule version, reviewer and date must exist before rendering; suppress the branch when content is missing. F6 asks about only one requirement once. Further admission checks belong on course details or with an adviser.
- Counting uses actual question screens after branching and reuse. Do not advertise only five responses while hiding compulsory qualification or budget fields. Time-to-complete claims are null until measured.

Validation checks: JSON parsing; expected question IDs and unique option IDs; valid selection bounds; all unknown options exclusive; optional/skip consistency; all conditional triggers refer to existing answers; full exact 16-category coverage; valid reuse source/target IDs and complete source-answer coverage; conditional budget field optional; maximum seven career and six course screens. Automated representative answer checks should reject mixed unknown/known selections and accept valid unknown-only and skipped optional answers.
